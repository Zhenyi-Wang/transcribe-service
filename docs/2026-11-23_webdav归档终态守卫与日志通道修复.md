# 2026-11-23 WebDAV 归档终态守卫与日志通道修复

## 问题

`webdav_archive.move_to_processed` 在"processed 回退读取成功后再归档"场景下把文件移进 `processed/processed/` 嵌套目录：回退时 `relative_path` 已被 `server.py._exec_webdav` 改写为 `processed/...`，而 `_to_processed_path` 对非 inbox 前缀"原样拼接"后又套一层 `processed/`，`shutil.move` 真执行。触发链：同步 HTTP 超时 → NoteFlow 重试 → 回退 → 成功 → 归档套娃 → 后续重试两层全空 → 任务失败。2026-11-14/17 三条 church-audio-sync 音频中招（晨祷会 22/23 章、平安中國系列43）。

次要缺陷：`logging.getLogger(__name__)` 未接 handler，INFO 级"归档完成"从未落过任何文件——归档链路三周无审计痕迹。

## 修复（2026-11-23 已上线）

`webdav_archive.py`：
1. `move_to_processed` 入口终态守卫：路径（lstrip("/") 后）为 `processed` 或 `processed/` 前缀 → 记日志跳过，绝不移动。设计原则：**读路径可以回退容错，写路径（移动）必须只认"源在 inbox"**。
2. logger 改 `setup_logger("webdav_archive")`，落 `logs/webdav_archive.log`。

测试：`tests/test_webdav_archive.py` 新增 2 例（processed 路径跳过、绝对路径形式防御），TDD 先红后绿；归档 10 项 + jobs 66 项全绿。已随服务重启生效，当晚真实流量 3 次正确拦截。
