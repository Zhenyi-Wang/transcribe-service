# GGUF 悬空指针崩溃根因与修复（2026-10-09 定案）

## 结论（一句话）

`qwen_asr_gguf/inference/llama.py` 的 `get_one_batch()` 把局部 ctypes 数组传给 `llama_batch_get_one()` 后直接返回——C 侧只存指针不复制数据，Python 函数返回后数组被 GC 回收，后续 `llama_decode()` 读悬空指针，表现为**概率性 `GGML_ASSERT(i01 >= 0 && i01 < ne01)` abort**（ggml-cpu/ops.cpp:5015，get_rows 查表索引越界）。修复：token 数组引用挂到 batch 对象上同存亡（commit `4454335`）。

## 为什么长音频必崩、短音频偶发

decode_token 每生成一个 token 调一次 `get_one_batch`。悬空指针是否踩坏取决于 GC 时机与内存复用：

- 短音频（几十分钟讲座）：调用数千次，偶发；
- 7 小时音频（水浒传 424 分钟）：~1.6 万次 decode，累积概率 → **~80% 必崩**（实测 4 轮任务全崩）。

修复后同场景连续两次全量通过（直跑 863s + mryk24 任务路径），零崩溃。

## 排查链（两次错误假设，供复盘）

1. **错误假设一：ASR context 偏置触发对齐越界**——依据是"无 context 直跑成功、带 context 任务路径连崩"。实际上崩与 context 无关（修复后带 context 全量通过），是调用次数堆概率。
2. **错误假设二：diarization 假死是崩溃根因**——diarization onnx CPU fallback 阻塞事件循环是**真实但独立的另一问题**（见下），修掉它后任务仍崩，才把怀疑点拉回 decode 路径本身。
3. **定位**：让 Fable 模型做独立代码审查，读 `llama.py:679-686` 发现 `llama_batch_get_one` 的指针语义 + 用 `libllama.so` 最小验证（batch `_objects` 为 None、缓冲区对象已释放、token 指针仍指原地址）实锤。
4. 历史旁证：9-02 曾在 llama.cpp 侧插桩想抓 i01 实值，但 abort 吞了输出缓冲从未拿到——**方向就错了，bug 不在 C 侧而在 Python 调用方的对象生命周期**。

## 修复代码

```python
def get_one_batch(token_id: int):
    token_arr = (llama_token * 1)(token_id)
    batch = llama_batch_get_one(token_arr, 1)
    batch._token_arr_keepalive = token_arr  # 挂引用同存亡，防 GC 回收后悬空
    return batch
```

## 关联问题与遗留

### diarization 超长音频假死（独立问题，已缓解）

onnx WeSpeaker 分离跑在 CPU Fallback（GPU provider 未生效），层次聚类 O(N²)：1 小时音频秒级、7 小时（~5000 段）分钟到小时级，且同步执行阻塞 FastAPI 事件循环 → transcribe 整体假死（下游表现为 fetch failed）。
**已缓解**：mryk24 douyin extractor 对 >2h 音频自动跳过 diarize（2026-10-08）。
**待根治**（另行立项）：① onnx CUDA provider 排查（为何 fallback）② 分离推理移出事件循环（to_thread）。

### 迁移官方 llama.cpp mtmd 路线：挂起（触发条件已定）

官方已原生支持 Qwen3-ASR（`ggml-org/Qwen3-ASR-1.7B-GGUF` + mtmd），本机实测 RTF≈0.016（快 2-4 倍）、质量同级。修复后迁移不再是必需，挂起为长期项。**重启评估的触发条件**：
1. 自研 ctypes 绑定再出同类别 bug（ABI/对象生命周期）——本类问题第二次发生说明税交不完；
2. Qwen3-ASR 大版本升级、自写 convert 跟不动；
3. 换卡/扩容想吃到官方路径硬件优化。

若迁移：官方 ASR + 30-60s 有界窗口 + **自研 aligner 可复用**（接口 `align(audio, text, language, offset)` 自带音频重编码，官方文本可直接送入）；注意窗口边界不能冒充句级时间戳、asr_engine_backend.py 只消费 `words` 需适配 segments、llama-server 生命周期纳入 pause/unload 管理。测试模型留存在 `/mnt/wsl/Emntvhdx/root/models/qwen3-asr-test/`（2.4GB）。

### 分段韧性（两 backend 通用能力，待做）

transcribe 侧长音频切段 + 段级检查点/缓存/重试——对任何 decode 层故障都降损（SIGABRT 同进程 try/except 接不住，需段级持久化）。
