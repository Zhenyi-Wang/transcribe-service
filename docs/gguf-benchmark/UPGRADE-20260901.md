# llama.cpp 升级 v0.3.0 基准对比（2026-09-01）

## 改动

升级自编译 llama.cpp：2026-04-29（fork commit 5438674）→ 2026-08-31 上游 master（518b7623，对应 release v0.3.0）。
构建：`cmake -B build -DGGML_CUDA=ON -DCMAKE_BUILD_TYPE=Release -DCMAKE_CUDA_ARCHITECTURES=75`。

配套代码改动：

- `qwen_asr_gguf/inference/llama.py`：同步新 ABI（`llama_model_params` 删 `use_mmap/use_direct_io/use_mlock`、加 `load_mode/lazy_mode/load_mtp`；`llama_context_params` 加 `n_rs_seq/n_outputs_max/n_outputs_max_per_seq/ctx_type/ctx_other`）；`LlamaContext` 支持 `type_k/type_v`（KV cache 量化）
- `qwen_asr_gguf/inference/asr.py` / `aligner.py`：`QWEN_ASR_KV_Q8=1` 环境变量开关 KV 量化（默认关）
- `lib/`：v0.3.0 新库（含新依赖 `libmtmd.so`），gitignore 不追踪；旧库本地备份 `lib.bak-20260429/`

## 测试环境

- GPU：RTX 2080 Ti 22GB（Turing sm_75，魔改卡）
- 音频：`test/test.mp3`（112.85s 中文祷告），5 轮取平均
- 配置：1.7B Q4_K GGUF decoder + int4 ONNX encoder（CUDA）+ 0.6B GGUF aligner（与生产一致）

## 结果

| 配置 | avg RTF | 相对基线 | decode | align |
|---|---|---|---|---|
| 基线（4-29 lib） | 0.0341 | — | 2.66s | 0.64s |
| **v0.3.0 默认** | **0.0265** | **-22%** | **1.84s（-30%）** | 0.63s |
| v0.3.0 + `GGML_CUDA_GRAPH_OPT=1` | 0.0481 | +41%（负优化） | 抖动 0.4~4.8s | — |
| v0.3.0 + KV cache Q8_0 | 0.0271 | -20%（与默认持平） | 1.87s | — |

结论：

- **纯升级即拿 -22%**（decode -30%），直接采用默认参数上线
- `GGML_CUDA_GRAPH_OPT=1`（concurrent streams）与此混合负载（ONNX encode + llama decode 共享 GPU）不兼容，弃用
- KV cache Q8_0 无速度收益（112s 音频 KV 太小），保留为长音频/显存不足时的备选开关
- 转录文本与升级前逐字一致；aligner 时间戳正常；asr-engine 端到端验证通过，单元测试 12/12 通过
