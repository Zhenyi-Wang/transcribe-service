## 2. 最近提交与假设边界

- `4454335` 修复单 token batch 的悬空指针：引用仅附着在当前 batch，释放后数组随之释放。20 万次真实 C batch 构造的轻量验证未见累积；forced-aligner 也不调用这条路径。保留修复，不重新引入 use-after-free。
- 修复前 ASR 日志有多次退出码 134 后自动重启。因此“WSL 连跑 12 天”不等于“ASR 进程连跑 12 天”；修复崩溃可能使原有累积问题暴露，但这不是 keepalive 引入泄漏的证据。
- `a79f4e5` 改变 embedding 的 cuDNN 策略，仍值得单变量回归。新默认保持原先删除 DEFAULT 后的等价策略 EXHAUSTIVE，未为规避问题而盲目回滚。
- CUDA Graph ID 是进程级递增计数器，不等于存活图数量；反复 warmup reset/complete 也不是泄漏证明。
- 转录开始/结束日志交错：06:48 完成的是 6770 秒任务，耗时约 709 秒；不是“8470 秒在 1.5 分钟异常完成”。
- reconstruct 可以存在数十 GiB 的理论分配，但**没有事故现场实际聚类数**，不可将示例 K=1000 写成事故事实。

## 3. 已复现的资源放大缺陷

旧路径是：请求线程池中完整解码音频 → 等分离推理锁 → 分离。一个 8470 秒的 16 kHz float32 PCM 约 517 MiB。等待锁的线程同样持有 PCM。

`asyncio.wait_for(asyncio.to_thread(...))` / `Task.cancel()` 只结束等待，不能终止已运行线程。时长探测失败得到 0，又把长任务套进 60 秒超时；失效任务继续排队或推理。分离失败还跳过整个转录缓存，重复请求再次完整跑 ASR 和分离。

另一条具体的大分配路径：pyannote 默认聚类训练 embedding 数不限，层次聚类距离矩阵 O(N²)；reconstruct 使用 float64 三维数组，且原先总说话人数不限。这些是需封住的资源路径，而非已确认的事故唯一来源。

## 4. 实施后的运行契约

### 分离工作进程

- `diarization/worker.py` 使用新 Python 解释器与私有 Pipe，只发送路径和配置；不 fork CUDA，也不通过 multiprocessing spawn 重导入 server.py。
- 一个任务取得准入后才在子进程解码。工作器繁忙立即降级，不创建排队线程、不解码额外 PCM。
- 超时、请求取消、任务异常或 RSS 超限：终止整个独立进程组，包括 ffmpeg，等待退出后再返回；后续任务可启动新的进程。
- 默认 RSS 阈值 4096 MiB，每 50ms 监测。**这是用户态监测阈值，不是内核硬配额，也不能完整计量 CUDA/WSL 驱动在宿主侧的提交量。**
- 默认处理 8 个任务后回收工作器，释放会话和进程资源。
- 暂停卸载仍在任务锁内检查世代，避免 resume 后被旧释放链误卸载；服务正常关闭时回收工作器。Linux 工作器还注册 `PR_SET_PDEATHSIG(SIGKILL)` 并核对父 PID，父服务异常退出时不等推理结束再发现 Pipe 断开。
- 若内核不可中断等待（D 状态）导致 KILL 后仍未退出，保留进程句柄并隔离；禁止向旧进程再提交，也不另开一个进程放大资源占用。待旧进程确实退出后才能重新启动，不能假称已经回收。

### 管线边界

- `max_num_embeddings=1000`：限制层次聚类训练输入数量，实际在 instantiate 后接入 pyannote clustering。
- `max_speakers=16`：自动聚类人数上限；显式人数超过上限直接报错，不静默裁剪。
- `max_reconstruction_mb=512`：按实际形状和簇数，在重建分配前核算至少双缓冲的 float64 字节，超过预算拒绝。后续其他阶段内存仍由 RSS 监测兜底。
- 管线阶段及重建前记录形状、簇数、预计分配、RSS，供未来区分 embedding / clustering / reconstruct / 驱动映射。

### 请求与缓存

- 同一事件循环、输入、context、diarize/no_cache 参数的在途转录共享独立任务，返回对象独立。取消任一请求不会带掉剩余等待者；最后一个请求离开才取消任务并等待分离进程回收。上传文件在任务内保留独立硬链接，路由删除原上传名不破坏剩余等待者，任务结束清理该链接。ASR 自身的 `to_thread` 无法强行终止是原有边界，本次没有伪装修复。
- ASR 基线缓存保留私有 `_asr` 词级时间戳；正常读取/API 剥掉内部字段。分离失败也保存已经完成的 ASR。
- 降级的 diarize 结果默认冷却缓存 3600 秒，单纯繁忙使用独立 `busy_cooldown=30` 秒，并显式返回 `diarization.status=degraded` / reason / retry_after，不伪装成分离成功，也不因短暂并发等待一小时。
- 冷却后复用 ASR，只重试分离，按保留的词级时间戳重新标注。旧缓存没有词级结果时使用段级重叠匹配。
- `no_cache=true` 保留“绕过读取缓存”的原语义，不绕过进程/内存保护，也不改变已有写缓存行为。
- 转录缓存同目录临时写入后原子替换；不再向调用方 dict 塞入 cached_at。短 TTL 与原 cache_days 共同生效。
- 时长探测保留原有 ffprobe 重试，并改用元数据回退，不再调用 torchaudio.load 完整解码来查时长。未知/无效时长使用有限 3600 秒预算，不退化成 60 秒。

配置字段与完整注释见 `config.yaml.example`。已有生产 config.yaml 缺少这些新字段时采用安全默认值，无需为启用边界复制凭据或整份配置。
